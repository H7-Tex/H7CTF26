# Polynonce: writeup

## The setup
An ECDSA signer on secp256k1 (order `n`) hands us eight approvals `(msg_i, r_i, s_i)`
and its public key `Q = d*G`. The story says nonces are a "deterministic chain",
each derived from the previous, to avoid an RNG call. The audit checked the two
usual things (no repeated nonce, no obvious bit bias) and both pass, because they
are true: the chain never repeats and looks uniform.

## Why the reflexes fail
- **Repeated `k`**: all `r_i` are distinct, so there is no shared-nonce recovery.
- **Biased nonce / HNP / LLL**: the nonces have no fixed leading zeros or short
  range, so lattice attacks on the most-significant bits find nothing.
- **Any off-the-shelf ECDSA nonce tool**: returns nothing. The weakness is not in
  a single signature, it is in the *relation between* signatures.

## The idea
The nonce is generated by a hidden low-degree recurrence. This challenge uses
degree 2:

    k_{i+1} = c2*k_i^2 + c1*k_i + c0   (mod n)

with secret coefficients `c0, c1, c2`. Two facts combine:

1. From the signature equation `s_i = k_i^{-1}(z_i + r_i d)`,

       k_i = s_i^{-1}(z_i + r_i d) = A_i * d + B_i   (mod n)

   where `A_i = s_i^{-1} r_i` and `B_i = s_i^{-1} z_i`. Every nonce is an **affine
   function of the one unknown `d`** (the `z_i = int(sha256(msg_i))` are public).

2. The recurrence is **linear in the unknown coefficients** `(c2, c1, c0)`.
   Writing it as `c2*k_i^2 + c1*k_i + c0 - k_{i+1} = 0`, each row

       [ k_i^2 , k_i , 1 , k_{i+1} ] . (c2, c1, c0, -1)^T = 0

   so the vector `(c2, c1, c0, -1)` lies in the (right) null space of the matrix
   whose rows are `[k_i^2, k_i, 1, k_{i+1}]`. For a non-trivial null vector to
   exist, every `4x4` block of that matrix must be singular:

       det [ k_i^2 , k_i , 1 , k_{i+1} ]_{i=t..t+3} = 0

## Recovering d
Substitute `k_i = A_i d + B_i`. Each entry becomes a polynomial in `d` (the
`k_i^2` column is degree 2), so the `4x4` determinant is a polynomial `P(d)` of
degree at most 4. It vanishes at the true key:

    P(d_true) = 0   (mod n)

Find the roots of `P` over `GF(n)` and keep the one satisfying `cand*G == Q`. With
eight signatures there are several overlapping `4x4` windows; the true `d` is a
root of every one, and the `d*G == Q` check removes any spurious roots.

In SageMath this is three lines:
```python
R.<x> = GF(n)[]
P = Matrix([[ (A[i]*x+B[i])**2, A[i]*x+B[i], 1, A[i+1]*x+B[i+1] ] for i in range(t, t+4)]).det()
cands = [r for r,_ in P.roots()]
```
The reference solver reproduces `P.roots()` in pure Python: reduce `P` mod `n`,
compute `gcd(P, x^n - x)` (the product of the distinct `GF(n)` roots), then split
it into linear factors by equal-degree splitting. No Sage required.

## Opening the flag
The private key seals the flag:

    key = SHA256(d as 32-byte big-endian)
    iv  = SHA256("Qx,Qy")[:12]      # decimal public-key coordinates
    flag.enc = AES-256-GCM(key, iv, FLAG) = ciphertext || 16-byte tag

Recover `d`, derive `key` and `iv`, GCM-decrypt `flag.enc` to this instance's
per-team `H7CTF{...}` and submit it. (The flag is a per-instance value injected
into the container, so it cannot be shared between teams.)

## Notes
- If you did not know the degree, you would sweep it: degree 1 (an LCG nonce)
  finds nothing here because the chain is genuinely degree 2; degree 2 solves it.
  That degree sweep is the whole intended difficulty.
- Real basis: "Polynonce" (Kudelski Security, DEF CON 31, 2023),
  github.com/kudelskisecurity/ecdsa-polynomial-nonce-recurrence-attack.
